# PrimServ — кабинет координатора, demo v0.1.0

**Черновой локальный прототип. Только вымышленные задачи. Не CRM и не рабочий
реестр кандидатов. Не подключён к боту, анкетам или производственным данным.**

Минимальный сценарий issue [#31](https://github.com/OleksandrKiris/kiris-jobs/issues/31):
три фиксированные задачи DEMO-01/02/03 → статус «К выполнению / В работе / Готово»
→ фильтр → сохранение локального прогресса → повторное открытие.
Нет свободного ввода, сотрудников, персональных данных, отправок или решений по найму.
Это срез направления 7, не завершённый кабинет или реестр знаний.

## Локальный запуск

1. Скачайте **всю папку coordinator-demo/** из точного commit PR. Первый download
   требует интернета. Не смешивайте файлы разных версий.
2. Откройте `index.html` в браузере. Все пять runtime-файлов локальные.
3. Если браузер ограничивает file:// или его хранилище, на собственном компьютере
   из этой папки можно запустить `python3 -m http.server 8080 --bind 127.0.0.1`
   и открыть `http://127.0.0.1:8080/`. Завершение сервера — Ctrl+C.

Оба способа требуют **браузерной приёмки**: в среде разработки разрешённый
предпросмотр сейчас недоступен. Команда выше — инструкция для локального
компьютера, не обход ограничений среды разработки и не опубликованный сервис.

## Что доступно без сети

После скачивания полного набора файлов логика доски, фильтры, языки и локальные
статусы не используют сеть. Здесь **нет service worker/PWA**, нет обещания SW
на file:// или первого запуска без загруженных файлов. Фактическое отключение
сети в браузере ещё не проверено; тесты подтверждают только код/обработчики.
Внешние ссылки PrimServ, вакансий, HYDRA и Telegram требуют интернета и открываются
в новой вкладке, оставляя кабинет на месте. Telegram/HRappka офлайн не обещаются.

RU, UK, PL и EN реализованы в интерфейсе. `?lang=ua` нормализуется в UK,
неподдерживаемый язык показывает EN с явным пояснением. Переход в HYDRA использует
`ua`, в каталог — `uk`. Язык и фильтр сохраняются в URL через replaceState;
при недоступном History API продолжают работать в памяти.

## Хранение и восстановление

- Единственный ключ: `primserv:coordinator-demo:v1`.
- Формат: `{ "version": 1, "statuses": { "demo-01": "todo", "demo-02": "todo", "demo-03": "todo" } }`.
- Сохраняются **только** статусы трёх фиксированных demo-задач при изменении.
  Нет имён, свободного текста, реальных приездов или дат работников.
- Неизвестный/повреждённый формат и недоступное чтение блокируют перезапись.
  Работа продолжается в памяти с видимым предупреждением. Запрет записи не
  уничтожает предыдущую запись. Никакой автоматической миграции/очистки.
- Сброс требует явного подтверждения и удаляет только собственный ключ.
  Если удаление запрещено, интерфейс предупреждает, что оно не гарантировано.
- file:// и приватный режим могут ограничивать localStorage. Не рассчитывайте
  на перенос данных между браузерами, устройствами или разными URL запуска.
- После обновления сохраняйте тот же локальный путь/origin. Текущий v1 совместим
  с тем же набором ID; неизвестные будущие форматы намеренно не преобразуются.

## Проверки

`node --test coordinator-demo/test.cjs` из корня repo: **23 теста**.
Внутри папки: `node --test test.cjs`. Зависимости не нужны, Node.js 20+.
Общий `npm test`: **136 тестов и штатные валидаторы**.
CI каталога не запускает отдельные тесты demo автоматически; проверяющий обязан
запустить их отдельно. Общие package.json и workflows не менялись.

Тестируются реальная модель/обработчики в DOM-стенде: четыре языка, фильтры,
пустые результаты, повторное открытие, фокус после скрытия карточки, отклонение
неизвестных ID/статусов, повреждённый/будущий/запрещённый storage, отказ записи,
отменённый/подтверждённый сброс и сохранение чужих ключей. Сетевые API запрещены
в стенде; исходники проверяются на отсутствие сетевых вызовов/форм/таймеров/SW.
Это не браузерная проверка и не тест телефона.

Runtime: 5 файлов, **32 770 байт** (из них официальный SVG 11 391 байт).
Логотип байт-в-байт равен `assets/primserv-logo.svg` основного repo.
Нет библиотек, CDN, шрифтов, трекинга, массовой загрузки фото/аудио и polling.
CSP: connect-src/form-action none. Фактический сетевой журнал пока не измерен.

## Публикация и откат

PR — draft, без merge/deploy. Действующие страницы, общий SW v220, 14 вакансий,
54 фото, инструкции, контакты и HRappka не изменяются.

**Важно для задачи10:** текущий `.github/workflows/pages.yml` запускается при
push main и загружает `path: "."`. Простое слияние включит этот модуль в Pages.
Новый online deploy здесь не разрешён. До merge необходимо отдельное решение
по безопасному исключению прототипа из production-артефакта соответствующим
владельцем либо другое согласованное размещение исходников. Эта задача не
меняет общий workflow и не создаёт новый repo ради обхода ограничения.

После приёмки и разрешённого способа сохранения/выпуска задача10 проверяет
свежие main/head, все тесты и expected-head guard. Откат исходников — отдельный
проверенный revert PR только этого модуля/журнала. Локальные статусы не удаляются
при откате кода; их удаляет только подтверждённый пользователем сброс.
