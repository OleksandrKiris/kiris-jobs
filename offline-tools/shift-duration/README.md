# PrimServ — длительность смены, прототип v1

Владелец: задача11. [Сценарий и приёмка — issue32](https://github.com/OleksandrKiris/kiris-jobs/issues/32).
Изолированная арифметическая утилита: начало/конец, явный переход через полночь,
перерыв в целых минутах, результат в часах/минутах. RU/UK/PL/EN; `ua` → `uk`,
неподдерживаемый язык → EN с видимым пояснением. Не табель, не зарплата,
не оценка норм рабочего времени; нет дат, DST и часовых поясов. Интервал >0 и <24ч.
Данные условий вакансий и процессы HRappka не используются и не меняются.

## Запуск и офлайн

Скачайте всю папку `offline-tools/shift-duration/` вместе с пятью ресурсами
`index.html`, `core.js`, `app.js`, `style.css`, `primserv-logo.svg` на устройство.
Откройте `index.html` в браузере. Классические скрипты, без ES-модулей/fetch/CDN,
сборки и установки зависимостей. При ограничении локальных файлов браузером:

```sh
cd offline-tools/shift-duration
python3 -m http.server 8080 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:8080/`; остановка Ctrl+C. Python нужен только для
этого альтернативного локального запуска, интернет ему не нужен. Это не сервер
данных и не публикация. Не открывать сервер на внешних интерфейсах.

Интернет нужен для первого скачивания и для переходов к компании, вакансиям,
HYDRA и Telegram. Ни один внешний ресурс не нужен для расчёта. Нет SW/PWA,
фоновой отправки, аналитики или предварительной загрузки медиа. Простое посещение
страницы онлайн не гарантирует офлайн-доступ без сохранённой локальной папки.

## Проверяемый сценарий

1. Выбрать UK; ввести 22:00 → 06:00, отметить следующий день, перерыв 30.
2. «Розрахувати»: 7 год 30 хв; весь интервал 8 год 0 хв.
3. Сменить язык — поля и результат остаются; выключить следующий день — ошибка.
4. Восстановить флажок, сохранить поля, перезагрузить: поля восстановлены.
5. Отмена удаления сохраняет данные; подтверждённое удаление убирает только
   собственную сохранённую запись, не текущие поля и не чужое хранилище.

Хранится только `{version:1,value:{start,end,nextDay,breakMinutes,lang}}` в
`primserv.offline.shift-duration.v1`, по явному нажатию. На общем устройстве
можно не сохранять. Повреждённый/будущий формат не перезаписывается: расчёт
продолжается, для нового сохранения нужно явно удалить старую запись.
При запрете/квоте storage используется память; reload тогда сбрасывает ввод.
Если чтение запрещено, запись тоже блокируется даже при доступном setItem:
невидимое прежнее содержимое не считается пустым. После восстановления чтения
повторное явное нажатие «Сохранить» снова доступно; фоновых повторов нет.
Для file:// поведение storage зависит от браузера, гарантий сохранения нет.

## Тесты и ограничения

```sh
node --test offline-tools/shift-duration/test.cjs
npm test
```

Собственные тесты проверяют арифметику, ошибки, локали, контроллер интерфейса,
reload/storage, запрет сетевых вызовов в коде, локальные зависимости и точное
совпадение официального SVG. DOM-стенд — не визуальный тест и не телефон.
Результаты реальной браузерной проверки и точный head фиксируются в PR.
Регрессия отказа чтения при разрешённой записи покрыта модельным и UI-тестом:
прежняя запись и чужие ключи сохраняются, расчёт остаётся на экране.
Собственных тестов: 16 (14 модели/контроллера + два теста CI-guard и контракта).
Это не браузерная проверка отказа storage.

### Подготовленный сценарий CI

`browser-acceptance.mjs` — модульный entry по контракту [PR39](https://github.com/OleksandrKiris/kiris-jobs/pull/39).
Он запускается только в GitHub Actions, с уже установленным Playwright и
`PLAYWRIGHT_PACKAGE`, `TESTED_HEAD`, `TESTED_BASE`, `BROWSER_REPORT` от общего runner.
Не запускать его локально как обход ограничений браузера/предпросмотра.
Сценарий проверяет SHA256 пяти ресурсов против exact head, открывает скачанную
папку через file:// уже без сети, проверяет 1280×900/320×900, клавиатуру,
полночь/ошибки, четыре языка/ua/ka, явное сохранение, reload/Back, сброс,
предыдущий v1/corrupt/future/denied read/write/remove и восстановление.
Любой внешний запрос, даже неуспешный, приводит к fail. Ссылки не открываются.
JSON, screenshots и traces сохраняются вне checkout/Pages, браузер закрывается.

**Сценарий подготовлен, но пока НЕ выполнен:** PR39 ещё должен принять владелец10.
Затем эта ветка согласуется с main, общий CI запускает module entry, а отчёт
и снимки проверяются перед снятием draft. Успех браузера каталога не является
приёмкой калькулятора. Узкий viewport не физический телефон; v1 fixture не
обновление ранее опубликованного продукта. Альтернативный HTTP-запуск и
экранный диктор этим сценарием не проверяются.

## Обновление и откат

Нет изменений общего SW/cache v220. У локального прототипа нет своего SW.
Если в будущем размещать его на origin каталога, отдельно проверить влияние
корневого SW; этот PR не является приёмкой такой интеграции.
Локальную копию обновлять заменой файлов папки; будущие версии должны сохранять
совместимость ключа/формата, не удаляя неизвестные данные. Не смешивать файлы
разных версий. Откат — отдельный PR удаления только этой новой папки и её
документации; нет миграций, зависимостей или изменений работающего каталога.
Не публиковать и не подключать вход самостоятельно: приёмка и merge — задача10.
