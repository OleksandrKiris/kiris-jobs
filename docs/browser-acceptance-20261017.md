# Приёмка каталога в Chromium / GitHub Actions

17.10.2026 пользователь явно разрешил Playwright/Chromium в существующем
GitHub Actions для проверки подготовленных версий. Это дополнительный
разрешённый способ приёмки при недоступном локальном preview.

PR38 продолжается в своей ветке. `.github/browser/catalogue.mjs` запускается
только в Actions, после обычных тестов и build/verify артефакта Pages.
Существующий статический сервер привязывается к 127.0.0.1 только на время
теста; сервер/Chromium завершаются в finally. Нового размещения сайта нет.
Playwright 1.56.1 устанавливается только в runner.temp; зависимости runtime
и package.json каталога не меняются. Запуск ограничен timeout job 10 минут.

Проверяются реальным Chromium окна 1280×900 и 320×900: клавиатурный вход,
PL→UK и ссылка обучения ua, поиск/страна/reload, вакансия, два существующих
фото/Escape/возврат фокуса, Back с контекстом, пустой результат/reset,
EN/KA/EN (в каталоге KA поддерживается), offline/reload и восстановление сети.
Отдельные контексты проверяют повреждённое и запрещённое storage.
Внешние запросы блокируются, форма не отправляется; HRappka проверяется
только как неизменённая ссылка. Реальная доставка анкеты не проверяется.
Существующие POST-счётчики посещения `/api/public/funnel` перехватываются
и записываются в отчёт без отправки. Любой иной POST/PUT/DELETE — ошибка теста.

Фиксируются head PR, base PR, фактический checkout (merge commit Actions),
SHA-256 активов артефакта, версия Chromium, окна, шаги, cache v220,
скриншоты и traces. Артефакт `catalogue-browser-<head>` хранится 7 дней.
Скриншоты нужно прочитать перед решением о выпуске. Успешный запуск не
означает проверку физического телефона или полноту всех сценариев продукта.

Офлайн — отключение сети контекста Chromium после успешной загрузки и
активации существующего SW. Первый запуск требует сети/полного локального
набора файлов. Сеть Telegram/HRappka этим не заменяется. Версия SW и все
runtime-файлы в PR38 неизменны; новой миграции кэша нет.

До merge: полный diff, npm test, тесты упаковки, успешный browser job,
просмотр снимков, свежие main/head и expected-head guard. Последний
исправный main: 32289688ab209c0985ca534a58ec04079824fbb0, cache v220.
После merge: Pages success, совпадение опубликованных активов и живой
маршрут каталога. Возврат отдельным проверенным PR; после добавления
прототипов нельзя возвращать публикацию всего корня. Тестовый код находится
в .github и не входит в Pages; добавляется лишь эта неподключённая документация.

Результат запуска и точный новый head будут записаны в PR после CI.
